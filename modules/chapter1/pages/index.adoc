= What Is the Automation Orchestrator?


Let's start with the most important question: what exactly is the automation orchestrator, and where does it fit in your automation story?
Red Hat Ansible Automation Platform introduces the automation orchestrator as a visual, workflow-based orchestration platform that gives you a single place to design, execute, and govern multi-step automation workflows that coordinate across tools, teams, and systems by combining task-driven steps, event-driven triggers, AI-assisted decision making, and human approvals in one visual, auditable workflow.

You already use AAP workflows to chain playbooks, job templates, and approvals across your systems. What Automation Orchestrator **adds is advanced conditional logic and dynamic decision-making** allowing your workflows to evaluate complex runtime data and intelligently route execution on the fly.


== Why Was the Automation Orchestrator Built?

As enterprise IT environments grow more complex, automation needs have evolved. Organizations are no longer just running scripts or playbooks in isolation. They are building automation that spans multiple teams, tools, domains and increasingly with AI assistance. The automation orchestrator was built because a new class of automation challenge emerged, one that requires coordinating across tools, teams, and modes of automation and that required a purpose-built solution.


The automation orchestrator was purpose-built to meet this need. It brings together the following into a single, governed, visual workflow:

- Existing Ansible automation
- External APIs and third-party tools
- Event-driven triggers
- Logic conditionals
- Human decision points
- AI-driven task agents


== What Is Multimode Orchestration?

One of the most important concepts in the automation orchestrator is its role in multimode orchestration. This means not being locked into a single style of automation as it supports three distinct modes that can be combined into a single workflow.

**Task-Driven**

This is structured, deterministic automation. You define a sequence of steps like call an API,  run an Ansible job, evaluate a condition, wait for a result  and it executes them in order. This mode is ideal when you know exactly what needs to happen and in what order.

**Event-Driven**

Workflows do not always need to be triggered manually. With event-driven triggers, your workflows can start automatically in response to something happening: a webhook call, an alert, or an external system notification. The automation orchestrator includes a dedicated Event-Driven Ansible trigger type that, when connected to your EDA environment, allows workflows to start automatically in response to events processed by EDA in real time.

**AI-Driven**

This is where the automation orchestrator enters new territory. Using Task Agent steps powered by large language models (LLMs), your workflows can include AI-assisted reasoning analyzing logs, generating remediation plans, interpreting unstructured data, and making decisions all within a governed workflow context.

[Note]
AI-driven automation is not just a feature, it represents a new mode of automation that organizations are beginning to adopt. The automation orchestrator is designed to be the platform where human-defined automation, event-driven automation, and AI-assisted automation come together in a single, auditable workflow.
